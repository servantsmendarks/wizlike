# UI 仕様（UI）

## 1. ステージ

- UI-01 論理解像度は縦 240×400。整数倍は端末ピクセル（CSS px × `devicePixelRatio`）で数える。論理 1px を何端末ピクセルで描くかの倍率 `k` は、画面（safe area の内側、UI-02）に収まる最大の整数とし、`#stage` を `transform: scale(k / devicePixelRatio)`（CSS 上の倍率）で拡大する。端末ピクセルで 1 倍も収まらなければ、収まる最大の小数倍にする。中央寄せ、余白は黒。ステージの位置（left/top）は 1/`devicePixelRatio` 単位（端末ピクセル境界）に丸め、丸めると safe area をはみ出す場合（内側の境界に寄せても収まらない場合）は丸めずに safe area を優先する（UI-02）。
- UI-02 `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`。`env(safe-area-inset-*)` を余白に足す。ステージは safe area の内側に収める。
- UI-03 フォントはピクセルフォント 1 種（美咲ゴシック 8×8 または PixelMplus10）【仮】。`@font-face` で同梱。文字サイズは 8px 固定、行間 10px。`image-rendering: pixelated`。
- UI-04 色は FC 風の固定パレット（`src/presenter/palette.ts`、54 色以内）。線画は黒地に白または淡緑の 1px 線【仮】。テーマ切替は無し。
- UI-05 body に `touch-action: none; overscroll-behavior: none; user-select: none; -webkit-touch-callout: none; -webkit-tap-highlight-color: transparent;`。
- UI-06 音は Web Audio。最初のタップで `AudioContext.resume()`。プロトタイプでは SE/BGM は任意（M6）。

## 2. レイアウト（縦持ち）

上から順に。数値は論理 px【仮】。高さは `config.ui.layout`（header / view / message / party / controls）に置き、合計が `config.stage.height`（400）と一致することを読み込み時に検証する。ビューの 150 は UI-20（`viewBox="0 0 240 150"`）で固定で、【仮】ではない（150 以外は検証エラー）。パーティは `party.size` 行 × 10px 以上（6 人で 60 以上。足りなければ検証エラー）。迷宮の画面の各部品（ボタン、メッセージ窓の文字領域と行数、パーティ欄の行、地図の overlay）は、表示層がこの区切りの各領域の原点と高さから配置を計算するので、config を変えれば追従する。操作領域の中身（十字ボタン 32px × 3 段など）が収まらない高さは起動を止めず、表示層が console.warn で知らせる。

| 領域 | 高さ | 内容 |
|---|---|---|
| ヘッダー | 16 | 階数・向き・現在地の簡易表示、設定ボタン。街では所持金 |
| ビュー | 150 | 迷宮: 線画（SVG）。戦闘: 敵グループの絵と名前・体数。街: 施設の絵（M4 では枠のまま） |
| メッセージ | 70 | GM の語り。文字送り。再生中のタップは UI-45 / UI-43。窓は指でスクロールしない。再生の外のタップで履歴の画面（UI-46。直近 `config.ui.messageHistory`（200）件【仮】）を開く |
| パーティ | 64 | 6 行 × 10px。名前（6 文字）・職業の略称（`classes[].abbr`）・HP 現在/最大・MP 現在/最大（`mpMax` が 0 なら空欄）・SAN・状態・SAN の段（UI-12）。行は押せない（状態はキャンプと酒場の「状態」UI-59 で見る） |
| 操作 | 100 | 迷宮: 矢印ボタン（前進・左・右・反転）とメニュー（キャンプ・地図）。キャンプ: 4×2 の枠か一覧（UI-53）。戦闘: コマンドメニュー。街: 施設メニュー |

- UI-10 メニューは DOM のリスト。1 項目の高さは 12 論理 px 以上、端末上で 40px 以上になるようにする。
- UI-11 スクロールはメニュー（操作領域の一覧）・履歴の画面（UI-46）・全滅の内訳（UI-56）・タイトルの一覧（UI-50）だけ。メッセージ窓とページ全体はスクロールしない。
  - 操作領域の一覧で末尾が 戻る / やめる の画面（街の各施設のページ、キャンプと酒場の一覧の段、戦闘の呪文・道具・対象）は、その項目を一覧の外の操作領域の右下（戦闘のメンバーの戻る・キャンプの [7] と同じ 56×40。操作領域の x178・y54）に固定し、残りの行を幅 168 の一覧（3 行が見え、多ければ縦スクロール）に置く。一覧は出すたびに先頭までスクロールして見せる。番号（数字キー）と対象の注目の順は今どおり末尾が 戻る / やめる。保留中の選択（階段など）は対象外（M4.5）。
- UI-12 パーティ欄の状態の列は、生きている者なら状態異常の短い名前の後ろに SAN の段（CH-53）の短い名前を足す（`party.san.uneasy` / `confused` / `broken`。normal は出さない）。死亡・灰はそれだけ。段は core の `sanStage` で決め、再生の途中の sanChanged でも描き直す（M5）。

## 3. 線画ビュー

- UI-20 `<svg viewBox="0 0 240 150">` 内に、視野（DG-12: 奥行き 0〜3 × 左中右）の各マスについて「正面壁」「左側壁」「右側壁」「扉」「階段の記号（上り・下り）」の `<path>` をあらかじめ置き、表示/非表示を切り替えるだけで描く。座標表は `src/presenter/views/dungeon-geometry.ts` に定数として持つ。階段の記号は、見えている階段のセル（DG-12 の VisibleCell.stairs。左中右のどの列でも）の床に描く。床の横線 3 本で、下りは上の線ほど広く、横線が奥へ下がっていく形（地図の V）、上りはその逆（地図の ^）。色は地図の階段と同じ。
- UI-21 遠近は奥行きごとに固定の矩形（例: 奥行き 0 が画面いっぱい、3 が中央の小さな矩形）。側壁は隣接する奥行きの矩形を結ぶ台形。奥行き d のセルの床は P_d と P_{d+1} の下辺の間（側壁の下辺に挟まれた台形）。階段の記号【仮】の横線は、床の奥の縁から高さの 1/4・1/2・3/4 に置き、幅は床の幅の 3/4・1/2・1/4（下りは上から広い順、上りは下から広い順）。中央の列はその高さの床の幅、左右の列は列の壁と同じ見えている帯を、いちばん手前の線の高さで測った幅を 3 本共通に使い、線は帯の縁（壁の縦線）に付かないよう帯の内側（縁から 1px 以上）に収める。
- UI-22 線は `stroke-width: 1`、`shape-rendering: crispEdges`。塗りは無し。扉は正面壁の内側の小さな矩形。
- UI-23 歩行・旋回の演出は、ビュー全体を 60〜100ms フェードするだけ【仮】（線画のスライドはしない）。
- UI-24 マップ画面は別の SVG。探索済みセルを 8px 角（盤が大きくて地図の領域に入らないときは min(8, 領域 ÷ 寸法) px）で描き、壁は線、扉は隙間、階段は記号、現在位置は三角形（向き付き）。地図本体のセルをタップすると、そのセルを選ぶ（UI-25）。
- UI-25 地図のタップ移動は 2 段階（選ぶ → 歩き出す）。
  - 吸着: 地図本体のタップ（UI-36。地図本体の SVG の左上からの論理座標）から、セルの中心（地図の原点から `(x*cell + cell/2, y*cell + cell/2)`）までの距離が `config.ui.mapSnapPx`（12 論理 px。ユーザーが決めた値）以内の探索済みのセルのうち一番近いもの（同じ距離なら y、次に x の小さい順。二乗距離の差が 1e-6 論理 px² 以下なら座標の換算の誤差とみなして同じ距離として扱う。M4.5）に吸着する。そのようなセルが無ければ何もしない（選択も変えない）。
  - 吸着したセルを core の `planRoute`（DG-15）で調べる。経路が `[]`（現在位置）なら何もしない（選択も変えない）。
  - `null`（探索済みのセルと辺だけでは届かない）なら、地図の題の行を「道が分からない。」（`map.noRoute`）に替え、選択を解く。地図は開いたまま。
  - 経路があればそのセルを選び、セルの外形の枠（accent 色）を点滅させて示す（Web Animations の繰り返し。演出スキップでは点滅せず枠だけ）。題の行は元に戻す。別のセルをタップしたら選び直す。
  - 選んだセルをもう一度タップするか、操作領域の「移動」（`map.go`。地図を開いている間だけ「閉じる」の真下に出す。選んでいないときは dim で押しても何もしない）を押すと、経路を引き直して歩き出す。地図を閉じると選択は消える（次に開いたときは選んでいない状態で、題も元に戻る）。選択は表示層だけの値で保存しない。
  - 歩き出すときは地図を閉じ、1 手目をすぐに送り、以後は再生の終わりから `settings.holdRepeatMs` おきに前進・旋回を 1 手ずつ送る（自動歩行。長押しの連打 UI-31 と同じ仕組み）。
  - 各手の結果で `routeStepOk`（DG-15）が偽なら止まる（遭遇・罠・階段の確認・壁・回転床・rejected。扉では止まらない）。遭遇で止まったら戦闘はそのまま始まる。最後の手を送り終えたら止まる。`routeStepOk` が偽の手と最後の手は、その手の結果が出た時点で（その手の再生を始める前に）自動歩行を終える。その再生中の入力は自動歩行の外として通常どおり受ける（拍のタップ UI-45 など）。
  - 歩いている間にステージのどこか（マウスは主ボタン）に触れる・操作に割り当てたキー（UI-33）を押すと止まり、その入力は捨てる（タップ・スワイプ・長押しのどれにもしない。送っている途中の 1 手はそのまま再生する）。窓のフォーカスが外れた・ページが隠れたときも止まる。
  - 歩いている間はスワイプを受けず（UI-30）、ボタンは反応しない。自動歩行は保存しない（SV-50）。

## 4. 入力

- UI-30 スワイプは、迷宮の画面（overlay・選択の保留が無く、`inputMode` が buttons でなく、自動歩行（UI-25）中でないとき）ではステージ全体で受ける（Pointer Events。UI-36 の共通の入力と同じ 1 か所）。ボタンの上で始まっても、閾値を越えたらスワイプで、そのボタンは反応しない。`pointerdown` の座標を起点に、移動量が `settings.swipeThreshold`（論理 28px【仮】、CSS px に換算＝× ステージの CSS 倍率 `layout.scale`）を越えた瞬間に、主軸（|dx| と |dy| の大きい方）で方向を確定して 1 回だけ発火し、`pointerup` まで再発火しない。上 = 前進、左右 = 指を動かした方へ旋回【仮】、下 = 反転。主軸が同値（|dx| = |dy|）なら縦とする。
- UI-31 前進を確定したまま指を離さなければ `settings.holdRepeatMs`（250ms【仮】）ごとに前進を繰り返す。壁に当たったら止める。戦闘・イベント・メニュー表示中は繰り返さない。長押し中に壁に当たったら「壁だ。」を 1 回だけ出して止まり、指（キー）を離すまではその長押しの続きとして前進を送らない（2 本目の指、スワイプと十字ボタンの併用、自動リピートのキーなど、押したままの間に重ねて届く前進の入力も無視する）。離して押し直すのは新しい長押しで、壁に向かっていればそのたびに 1 回出る。扉・遭遇・階段などで止まったときも同じ。長押しは、前進の結果が moved の後に hpChanged（迷宮の毒の 1 歩。CH-43）しか伴わなければ続ける。message・遭遇・lifeChanged などを伴えば止まる。前進ボタンは、短く離すと 1 歩、動かずに `holdRepeatMs` 押し続けると連打を始め、離すと止まる（UI-36 の「動かずに離した」と長押しの両立）。
- UI-32 矢印ボタンも常に表示する。設定 `inputMode` で `swipe` / `buttons` / `both`（既定 both）。矢印ボタンは「動かずに離した」ときに反応する（UI-36。前進の長押しは UI-31）。
- UI-33 PC ではキーボードで操作する。
  - ↑ 前進、←→ 旋回、↓ 反転、Enter / Space 決定、Esc 戻る、数字でメニュー選択。
  - WASD（W 前進・A 左・D 右・S 反転。矢印キーと同じ）。大文字でも効く。矢印キーが場面ごとに意味を変える所（履歴の画面・戦闘の対象の一覧の ↑↓ など）でも W が ↑、S が ↓ と同じに働く。日本語 IME がオンで key が文字に決まらない（"Process" など）ときは、キーの位置（code の KeyW / KeyA / KeyS / KeyD）で決める。
  - Ctrl・Meta・Alt との組み合わせは操作にしない（ブラウザの既定動作に任せる）。Shift は許す（大文字の W など）。修飾キー無しで押したキーは、Ctrl などを押しながら離しても離したことにする。
  - 再生中の Enter / Space は拍のタップ（UI-45 / UI-43）と同じ。
  - 履歴の画面（UI-46）は Esc / Enter / 1 で閉じ、↑↓ で 3 行ずつ動かす。
  - 戦闘の対象の一覧では、↑↓ で注目を動かし、Enter で注目している項目を選ぶ。
  - タイトル（UI-50）は 数字で n 番目、Enter で先頭、Esc でやめる。
  - 街（UI-52）は 数字で n 番目の枠・行、Enter で先頭、Esc で 1 つ上のページ。
  - 全滅の内訳（UI-56）は Enter / Esc / 1 で「街へ」。
  - 迷宮のメニュー（UI-53）は 1 でキャンプ、2 と m で地図。キャンプと酒場の状態・装備・並び順（UI-53 / UI-59）は 数字で n 番目の枠・行（空き枠は無視）、Enter で先頭の押せる項目、Esc でやめる（キャンプの top では戻る = 閉じる）。
  - 地図（UI-24 / UI-25）は Esc / m / 1 で閉じる、2 で移動（選んでいるときだけ）、Enter は選んでいれば移動・いなければ閉じる。
- UI-34 iOS Safari のタブ表示では画面左端からのスワイプがブラウザの「戻る」になる。ステージの左右の全高に 12 論理 px の非反応帯を置く【仮】（`config.input.edgeDeadZonePx`。境界ちょうどは反応する）。非反応帯で始まった押下はスワイプの起点にしないが、タップは通す。
- UI-35 入力はすべて `Command` に変換して `execute` に渡す。表示層で入力の意味を解釈しない（例: 前進できるかの判定は core が `blocked` で返す）。
- UI-36 共通のタップ。押せるもの（ボタン・一覧の行・戦闘の枠・キャンプの枠・敵の絵・メッセージ窓など）は、Pointer Events の「動かずに離した」で反応する。ステージの 1 か所（`input/tap.ts` の `attachStageInput`）で受け、押した要素は登録（`onTap`）で探す。
  - 押してから離すまでの移動が `settings.swipeThreshold`（UI-30 と同じ閾値）以上になったら取り消す（スクロールやスワイプの途中で行が押されない）。`pointercancel` も取り消し（スワイプ中・長押し中なら離したものとして扱う）。
  - 追うのは 1 本目の指（マウスは主ボタン）だけ。押している間はその要素に押下の見た目（class `is-pressed`）を付ける。
  - `click` には反応しない。例外は、キーボードの Enter で起きた click（`detail` が 0）を同じタップとして扱うことだけ。
  - 再生中（UI-44）のタップは、オート解除を除いてどこを押しても拍のタップ（UI-45 / UI-43）になる。
  - 名前の入力欄（UI-51）は例外で、上の押下を追わず、touchend も止めない。入力欄の外を押したら入力欄のフォーカスを外す。
- UI-37 ダブルタップの拡大の抑止。`#stage` 以下に `touch-action: manipulation`、迷宮でスワイプを受ける間（UI-30）は画面に `swipe-on` を付けて `touch-action: none`（ボタンの上で始めたスワイプがブラウザのパンにならないように）、縦スクロールの容器（UI-11）は `pan-y`。`#stage` の `touchend` を `passive: false` で受け、入力欄の上でなければ `preventDefault` する。body の `none`（UI-05）は残す。viewport の `user-scalable` には頼らない。

## 5. ダイスと演出

- UI-40 `dice` イベントは `{label, rows[{label, base, dice, total}], rule, result}` で、label / rows[].label / rule / result はどれも strings のキーと params（TextRef）。1 件の判定を 1 つの箱で見せる。箱はビューの x8・幅 224・下端 y146 に置き、高さは 8 + 10 ×（行数 + 3）。中身は上から 見出し（label）/ 各行「{label} {base}`dice.plus`{目…}`dice.total`」（base が null なら「{label} {目…}」で、目が 1 個なら合計を繰り返さない）/ 基準（rule）/ `dice.arrow`{結果}。演出は 行ごとに目を 1 個ずつ止める（1 個 300ms【仮】）→ その行の合計 → 次の行 → 基準 → 結果。新しい dice は前の箱を置き換える（積まない）。続く message の間は残し、message と dice 以外の次のイベント（または再生の終わり）で消す。ただし `beat`（UI-45）では、その拍の待ちの後に消す。全滅の 2d10（label `dice.wipe`）は、その後の message 以外のイベント（復活の lifeChanged / hpChanged / statusChanged、levelDown など。パーティ欄の更新はそのまま行う）でも消さず、`wipe` の前の待ち（UI-56）の後に消す。`skipAnimations` では最終の段だけを即時に出す。演出の途中で拍の中のタップ（UI-45）があれば、残りの段を飛ばして最終の段を出す。dice を受けたら、メッセージの履歴（UI-46）に 1 行の要約「{label} {行1} / {行2} / {基準}`dice.arrow`{結果}」（区切りは `dice.sep`）を残す（窓には出さない）。total は base（null なら 0）+ 出目の和で、将来の出目補正（M5 以降）は base に足すか行を足して表す。各判定の中身:

  | 判定 | label | 行 | 基準（rule） | 結果（result） |
  |---|---|---|---|---|
  | 先手（CB-04） | `dice.initiative` | `dice.side.party` / `dice.side.enemy`（base = floor(agi 平均)、1d10） | `dice.initiative.rule`（diff / need / ambush。ambush = need） | `dice.initiative.party` / `enemy` / `none` |
  | 不意打ちの察知（CB-04 / EV-42、M5） | `dice.ambushAvoid`（{name}） | `dice.row.roll`（base null、d100） | `dice.rule.rate`（rate = ambushAvoid の最大） | `dice.ambushAvoid.ok` / `ng` |
  | 逃走（CB-50） | `dice.flee` | `dice.row.roll`（base null、d100） | `dice.rule.rate`（rate = 成功率） | `dice.flee.ok` / `ng` |
  | 習得（MG-21） | `dice.learn`（spell = 呪文名） | `dice.row.roll`（base null、d100） | `dice.rule.rate`（rate = 成功率） | `dice.learn.ok` / `ng` |
  | 全滅（TW-22） | `dice.wipe` | `dice.row.roll`（base null、2d10 の 2 個） | `dice.wipe.rule`（帯の min / max） | `dice.wipe.result`（band = 帯の name） |
  | 制止（EV-20/21、M5） | `dice.restrain` | `dice.restrain.stopper` / `dice.restrain.actor`（{name}。base = 制止者の iq / 行動者の agi、各 1d10） | `dice.restrain.rule`（diff = 制止者の合計 − 行動者の合計） | `dice.restrain.ok` / `ng` |

  不意打ちの察知の箱は先手判定とは別の system の拍。制止の箱は拍の外で、続く message を 1 件出した後でタップを 1 回待ち、待ちの後に消す（UI-55）。他の拍の外の箱（習得など）は待たない。
- UI-41 演出は `GameEvent` の `kind` ごとに `playback.ts` の 1 関数に対応させる。各関数は Promise を返し、`settings.skipAnimations` が真なら即座に解決する。`skipAnimations` が省くのは 文字送り・ダイスの動き・点滅・被弾のフラッシュ・揺れ・撃破のフェード・ビューのフェードだけで、戦闘の拍の待ち（UI-45）とタップ待ちは省かない（CLAUDE.md §3-9）。
- UI-42 被弾: パーティ行のフラッシュ（`opacity` 2 往復、120ms）。敵の被弾: 敵の絵のフラッシュ。全体攻撃: ビュー全体の揺れ（`translate` ±2px、150ms）。すべて WAAPI。被弾のフラッシュは HP の減少（`hpChanged` の delta < 0）を契機にする（味方はパーティ行、敵はグループの絵）。`attack` イベントには演出を付けない。全体攻撃の揺れは、対象が `enemyGroup` / `allEnemies` で effect が damage の呪文のとき。敵の撃破（`lifeChanged` dead）で体数を 1 減らし、0 になったら絵を消して列を隠す。
- UI-43 メッセージの文字送りは `settings.textSpeed`（1 文字 30ms【仮】、0 で即時）。タップで残りを即表示。戦闘の拍（UI-45）を除き、次のメッセージをタップで待たない。拍の外では、1 回目のタップで今の文を即表示し、同じ再生の中で 2 回目のタップがあれば残りをすべて即表示する（playback の `Player.tap()`。ビューのフェードも 0 にする）。拍の中のタップは UI-45。再生中の Enter / Space もタップと同じ。全文の履歴は直近 `config.ui.messageHistory`（200）件【仮】を残す。
  - 窓は指でスクロールしない（overflow hidden・touch-action none）。窓には直近の文だけを出し、いつも末尾を見せる。
  - 窓のタップは、再生中ならステージ全体のタップと同じ（UI-36 / UI-45）。再生の外で文字送り中なら今の文の即表示、それ以外で overlay が無ければ履歴の画面（UI-46）を開く。地図などの overlay は窓を覆っているので押せない。
- UI-44 イベント再生中の入力は無視する（ただしメッセージ送りのタップは受ける。ステージのどこのタップと Enter / Space も、拍のタップ待ちを進めるタップ（UI-45 / UI-36）として受ける）。再生が終わってから次の入力を受け付ける。例外: オート戦闘中の「オート解除」ボタンと Esc / Enter / 1 キーは、再生中とオートの連鎖の途中でも受け付けるが予約だけを立て、連鎖の次の段で `battle.auto off` を送る。連鎖も再生も動いていないときに押したら、すぐに `battle.auto off` を送る。再生中・連鎖の途中に押したら、core の状態（そのラウンドの CB-43 で既に解けた、など）に関係なくボタンを予約の表示（`battle.autoStopping`）にする。予約を立てるのは今の state がオート中のときだけで、既に解けていれば何も送らない。`battleEnd` を再生した後は、戦闘の入力の UI（ヘッダーの問い・オート解除・パーティの選択）を下げ（ヘッダーは空）、続きの再生（全滅の内訳を開く前の待ち、勝利・逃走の screen{dungeon} まで）では出さない。同じく、コマンドを送ってから再生が終わるまでは、そのコマンドで閉じた入力の UI（ヘッダーの問い・選択肢）を出さない（ヘッダーは空、操作領域のボタンは出さない）。手動の `battle.flee` / `battle.repeat` / `battle.resolve` を送ったときと、全滅の 2d10 を出したとき（戦闘の外の全滅も。迷宮のヘッダーと十字ボタン・キャンプ・地図を下げる）がこれに当たる。オート中のラウンドの再生は「オート戦闘中」とオート解除を出したままにする。再生の後に入力へ戻るときは、再生の最後の同期で問いと選択肢を出し直す。その間のタップは、ステージのどこでも拍のタップ（UI-45）になる。それ以外の入力は、再生中と連鎖の途中は引き続き捨てる。地図のタップ移動の自動歩行（UI-25）の間の入力は、再生中かどうかに関係なく歩行を止めるだけで、その入力は捨てる（拍のタップにもしない）。ただし止まることが決まった手（UI-25 の `routeStepOk` が偽の手と最後の手）の再生は自動歩行の外とする。
- UI-45 戦闘の拍の再生。core の `beat {phase, auto}`（CB-55）で区切って見せる。迷宮・街の再生には拍が無く、待たない（例外: 全滅の 2d10（UI-56）と制止の箱（UI-55）のタップ待ち）。
  - 次の `beat` の前と、拍の中で戦闘の外への `screen`（dungeon / town）か全滅の `wipe`（UI-56）を受けたときの前で、直前の拍の後に message か dice が出ていれば待つ。手動（直前の拍の `auto` が偽）はタップ待ち（続きの三角を点滅させる。演出スキップでは点滅しない）、オート（`auto` が真）は `settings.autoBeatMs`（200 / 400 / 600、既定は `config.ui.autoBeatMs` の 400【仮】）だけ待つ。中身に文もダイスも無い拍の後は待たない。
  - 再生の終わりは、オートなら同じ待ちをする（オートのラウンドの間隔はこれで作る）。手動はダイスが出ているときだけ待つ（遭遇の先手判定を読ませる）。
  - 手動かオートかは `beat.auto` だけで決める（表示層は state から推測しない）。
  - 待ちは `skipAnimations` でも省かない（UI-41）。オートの待ちは WAAPI の `animation.finished` で測る（setTimeout は足さない）。
  - タップ: タップ待ちなら解く。拍の中（待っていない）なら今の拍の残り（文字送り・ダイスの動き・フラッシュなど）を即時にするが、拍は飛ばさない。拍の外は UI-43。
- UI-46 履歴の画面（overlay）。ビューとメッセージの範囲（既定 y16..235）を覆う。題（`history.title`）と、全文（メッセージと判定の要約。UI-40）を古い順に並べた縦スクロールの一覧で、開いたら末尾を見せる。一覧の見える高さは行の高さ（10px）の整数倍にし、余りは題との間の余白にする（末尾まで送ったときに最上段の行が途中で切れない）。操作領域には「閉じる」だけを置き、Esc / Enter / 1 でも閉じる。↑↓ で 3 行ずつ動かす。開けるのは街・迷宮（イベントの選択を待つ間を含む）・戦闘で、再生中・連鎖の途中でなく、他の overlay が無いとき（再生の外のメッセージ窓のタップ。UI-43）。再開時（SV-50）には開かない。

## 6. 画面

- UI-50 タイトル: ゲーム一覧（SV-12）、設定。一覧の行（1 行目 リーダー名・生存 n/6・踏破数、2 行目 最終更新日時。updatedAt の降順）→ 新しく始める → 設定 の 1 本のリスト。行を選ぶと 続きから / 削除 / やめる（読めない記録は続きからを dim にし、削除はできる）。削除は確認 2 段階で、確認の先頭は「やめる」。上限（SV-11）は「新しく始める」を押した時点で判定する。キーは 数字 n → n 番目、Enter → 先頭、Esc → やめる。遊んでいる途中からタイトルへ戻る UI は作らない。書き出し・読み込みは M6。

- UI-54 戦闘
  - 行動と結果は拍（UI-45）で区切って見せる（宣言 → 命中とダメージ → それで起きたこと）。
  - ビュー: 敵グループごとに絵と、絵の下のラベル「{番号} {名前} ×{体数}」（strings `battle.groupLabel`。2 行まで折り返し、3 行目以降は「…」で省く）。列の区切り線や列の枠は描かない。列は幅 56・間 4 で中央寄せ。体数 0 の列は詰めずに隠す。番号は、体数が 1 以上のグループを添字順に数えた順位で、対象の一覧の番号と同じ。
    - ラベルは判定の箱（UI-40。戦闘で出る箱は 1〜2 行で上端 y98 / y88）と重ならないよう、絵を上に寄せる（ビュー座標。2 列以上は絵 48×48 の y8..55・ラベル y58..77、1 列は絵 64×64 の y2..65・ラベル y68..87）。ラベルは注目の枠（絵 ±2）のすぐ下（M4.5）。ラベルの幅は 2 列以上なら注目の枠と同じ x と幅 52（隣のラベルと 8px 空け、3〜4 グループで 1 行につながって見えないようにする）、1 列は列の箱の幅 56（M4.5）。
  - パーティの選択: ラウンドの始めに出す（2 列 × 2 段: 戦う・前回と同じ / 逃げる・オート）。逃げられない戦闘では「逃げる」を dim にする。「前回と同じ」は `battle.repeat`、「逃げる」は `battle.flee`、「オート」は `battle.auto` on を送る。
  - メンバーの枠: 「戦う」で出す（上段 攻撃・呪文・防御・道具、下段の右端 戻る）。メンバーの「戻る」は、並び順で 1 つ前の行動可能なメンバーへ戻る（入力済みでも選び直せる）。先頭のメンバーではパーティの選択へ戻る。
  - 一覧: 呪文・道具・対象は一覧で、末尾が戻る（親の段へ。UI-11 の固定の位置）。
  - 対象の選択:
    - 体数 1 以上の敵グループが 1 つだけなら、敵の対象の一覧を飛ばしてそのグループを選ぶ。
    - 対象の一覧の初期の注目は、並び順で 1 つ前の行動可能なメンバーの入力の対象（今も選べるとき）。無ければ先頭。
    - 一覧で注目している項目（キーの上下・ポインタが触れている項目）の行に枠を付け、その敵の絵に枠を付けて点滅させる。演出スキップでは点滅せず枠だけにする。絵のタップでもその対象を選ぶ。
  - 全員分の入力が揃うと `battle.resolve`。手動のラウンドの解決の後と、CB-43 でオートが解除された後は、パーティの選択に戻る。
  - 押せない選択肢は dim 色で出す。オート中は「オート解除」だけを出す。「オート解除」は、解除の後に出るパーティの選択の「戦う」と同じ位置・大きさに出す（CB-43 で解けた直後の押し直しが、コマンドを送る 前回と同じ・逃げる・オート の枠に当たらないように）。入力中のメンバーの名前はアクセント色にする。
  - キー: 数字・Enter・Esc。対象の一覧では ↑↓（W / S）と Enter（UI-33）。オート中は Esc / Enter / 1 で解除。
- UI-55 イベント（M5）: core の `screen: event` は迷宮の画面の上で見せる（線画・ヘッダーの現在地・メッセージ窓・パーティ欄はそのまま）。選択肢は保留中の選択（pendingChoice kind event。ラベルは `event.<eventId>.choice.<choiceId>`）の一覧で、戻るは無く UI-11 の固定は使わない。Enter で先頭、数字で n 番目。選択を待つ間はスワイプ・十字ボタン・前進の長押し・地図・キャンプを受けない。履歴と debug パネルは開ける。衝動の行動者（`eventStarted` の actorId）は、その再生の間、名前を accent 色にし行を点滅させる（400ms の矩形波。演出スキップでは点滅せず色だけ）。再生の終わりで消す。`eventStarted` を受けたら十字ボタンを下げる。制止の判定の箱（UI-40）は、続く message を 1 件出した後でタップを 1 回待ってから消す（先に message・dice 以外のイベントか再生の終わりが来たらそこで待つ。演出スキップでも省かない）。`screen{event}` と、イベントから戻る `screen{dungeon}` ではビューをフェードしない。
- UI-56 全滅: GM の語り → ダイス → ペナルティの内訳（失った金額、アイテム名、EXP と誰がレベルダウンしたか）→ 街へ。
  - 内訳は `wipe` イベント（PenaltyResult）で開く overlay（ビューとメッセージの範囲。地図と同じ）。行は 帯の名前・出目・台帳で失ったもの（金と品の数。無ければ「無かった」）・所持金の損失・失った品（無ければ「なし」）・各人の EXP（Lv が下がった者は Lv の変化）。溢れたら縦スクロール。
  - 戦闘の全滅（拍の中の `wipe`）は、内訳を開く前に UI-45 の待ち（最後の拍の語りと 2d10 を読ませる。全滅の拍は system で `auto` が偽なのでタップ待ち）をし、拍の外に出てから内訳を開く。戦闘の外の全滅（迷宮の歩行中の CH-44 など。拍の外の `wipe`）も、内訳を開く前に 2d10 の箱を出したままタップを 1 回待つ（続きの三角。演出スキップでは点滅しない。手動のタップ待ちは演出ではないので演出スキップでも省かない）。どちらも待ちの間は 2d10 の箱を出したままにする（UI-40）。再生は内訳で入力を待たない。後続の街に入る処理（語り・SAN・救済の申し出・街の画面）は overlay の下で再生し、操作領域の「街へ」（Enter / Esc / 1）で閉じて街のメニューを出す。
  - 内訳は PenaltyResult だけで描く（state を引かない）。再生の途中でリロードすると内訳は見られず、街から再開する（SV-50）。
- UI-57 設定: 演出スキップ、文字速度、入力モード、音量、書き出し・読み込み。M2 では UI-57 の代わりに、debug パネル 1 枚（ステージの計測値、1px の模様、設定の仮 UI: スワイプ閾値・長押し間隔・文字速度・演出スキップ・オートの速さ（UI-45。押すたびに 200 → 400 → 600ms と巡回）・入力モードの 6 行、その下に最後に確定したスワイプの表示、ボタンの段（全員HP1・既定に戻す・ポインタ・閉じる。y342 の 56×32）、その下の 2 段目（y376 の 56×22）に SAN段↓・イベント・罠の前・階段前（M5。開発用））を置く。「既定に戻す」はオートの速さも既定値に戻す。タイトルの「設定」、ヘッダーの設定ボタン、F2 から開く。
  - 全員HP1（開発用。全滅の流れを実機で確かめるため）: 街・迷宮・戦闘のときだけ反応し、再生中・連鎖の途中は捨てる。パネルを閉じてから `debug.hpOne` を送る。core は title（party が空）だけ rejected `no party` にし、それ以外（保留中・戦闘中・街を含む）は、並び順に life alive で hp が 1 でない者の hp を 1 にして `hpChanged`、最後に message `debug.hpOne` を出す（変化が無くても出す）。dead / ash は変えない。乱数は使わない。hp 1 で行動不能になる者はいないので、迷宮の戦闘外でも全滅処理は起きない。本番のビルドでも出す（debug パネル自体が設定の仮 UI のため）。
  - SAN段↓・イベント・罠の前・階段前（開発用。M5 の性格・イベント・SAN を実機で確かめるため）: 迷宮のときだけ反応し、パネルを閉じてから `debug.sanDown` / `debug.warp{event|trap|stairsDown}` を送る。sanDown はリーダー以外の生存者の SAN を 1 段下げ（境の 1 つ下、錯乱の次は 0。sanChanged と段の message は通常どおり、最後に message `debug.sanDown`）、迷宮の戦闘外なら選択を待つ間も受け付ける（迷宮の外・戦闘中は rejected `not in dungeon`）。リーダーが行動不能なら、行動可能な者がいなくなった時点で全滅処理になる。warp はその階の実効の構造で、目標のセル（kind event、pit / spinner の罠、下り階段）を添字順に、N・E・S・W の順に辺で通じた通路・部屋のセルを探し、最初のものへ移って目標を向く（moved と message `debug.warp.<to>`。遭遇・毒・罠は起こさない）。行き先が無ければ state を変えずに message `debug.warp.none`（rejected にすると実機では何も起きないように見えるため）。warp は保留中は受け付けない（E3）。どちらも乱数は使わない。2 ページ目では出さない。ボタンの高さ 22 は UI-10 の 12 論理 px 以上だが、他のボタンの一辺 30（TOUCH_MIN_LOGICAL）は満たさない（開発用の例外）。
  - ポインタの記録（開発用。M4.5）: 「ポインタ」で 2 ページ目に切り替え、直近 20 件のポインタイベント（pointerdown / pointerup / pointercancel / lostpointercapture。pointermove は記録しない）を古い順に 1 行（10px）ずつ出す。各行は performance.now() の ms（整数）・種類・ステージの論理座標（整数。pointercancel / lostpointercapture で clientX と clientY が両方 0、つまり座標が渡されなかったときは「-」）・対象（押せるもの（data-tap の祖先）があればそれ、無ければ当たった要素自身について「{tag} {aria-label か文字}」。どちらも無ければ「{tag}.{class の先頭}」。16 文字まで）。記録は表示層だけの 20 件の輪で、保存しない。パネルを開いている間に始まった押下は記録しない（開いたタップの down / up までは残る）。2 ページ目では「ポインタ」が「設定」に変わり（押すと 1 ページ目へ）、全員HP1・既定に戻すは出さない。パネルは開くたびに 1 ページ目から出す。
- UI-58 （M4.5 で廃止。パーティの行のタップで開く詳細は UI-59 のキャンプの「状態」に置き換えた）
- UI-59 キャンプの「状態」（M4.5）: 迷宮のキャンプの「状態」と酒場の「状態を見る」から開く。キャンプのパネル（ビュー領域）に出し、名前の 6 枠で人を切り替える。「やめる」・Esc で戻る（キャンプは top、酒場は酒場の一覧）。
  - 表示する項目（旧 UI-58 と同じ）: 名前、種族、職業の正式名（`classes[].name`）、レベル、経験値、HP/MP/SAN（現在/最大）、状態、能力値 6 つ、装備 6 枠（名前は鑑定を反映した表示名。空きは「なし」）。
  - 14 行（10px）に詰める: 名前 / 種族・職業 / レベルと経験値 / HP・MP・SAN / 状態 / 能力値 2 行 / 「装備」/ 装備 6 行。下端は 144 でビュー領域（150）に収まる。
