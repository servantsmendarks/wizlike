# UI 仕様（UI）

## 1. ステージ

- UI-01 論理解像度は縦 240×400。`#stage` を `transform: scale(k)` で拡大し、`k` は画面に収まる最大の整数（収まらなければ小数）。中央寄せ、余白は黒。
- UI-02 `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`。`env(safe-area-inset-*)` を余白に足す。ステージは safe area の内側に収める。
- UI-03 フォントはピクセルフォント 1 種（美咲ゴシック 8×8 または PixelMplus10）【仮】。`@font-face` で同梱。文字サイズは 8px 固定、行間 10px。`image-rendering: pixelated`。
- UI-04 色は FC 風の固定パレット（`src/presenter/palette.ts`、54 色以内）。線画は黒地に白または淡緑の 1px 線【仮】。テーマ切替は無し。
- UI-05 body に `touch-action: none; overscroll-behavior: none; user-select: none; -webkit-touch-callout: none; -webkit-tap-highlight-color: transparent;`。
- UI-06 音は Web Audio。最初のタップで `AudioContext.resume()`。プロトタイプでは SE/BGM は任意（M6）。

## 2. レイアウト（縦持ち）

上から順に。数値は論理 px【仮】。

| 領域 | 高さ | 内容 |
|---|---|---|
| ヘッダー | 16 | 階数・向き・現在地の簡易表示、設定ボタン |
| ビュー | 150 | 迷宮: 線画（SVG）。戦闘: 敵グループの絵と名前・体数。街: 施設の絵 |
| メッセージ | 70 | GM の語り。文字送り。タップで即表示、もう一度で次へ。履歴はスクロール |
| パーティ | 64 | 6 行 × 10px。名前（6 文字）・HP・MP・SAN・状態。行タップで詳細 |
| 操作 | 100 | 迷宮: 矢印ボタン（前進・左・右・反転）とメニュー（道具・呪文・地図・並び）。戦闘: コマンドメニュー。街: 施設メニュー |

- UI-10 メニューは DOM のリスト。1 項目の高さは 12 論理 px 以上、端末上で 40px 以上になるようにする。
- UI-11 スクロールはメニューとメッセージ履歴だけ。ページ全体はスクロールしない。

## 3. 線画ビュー

- UI-20 `<svg viewBox="0 0 240 150">` 内に、視野（DG-12: 奥行き 0〜3 × 左中右）の各マスについて「正面壁」「左側壁」「右側壁」「扉」の `<path>` をあらかじめ置き、表示/非表示を切り替えるだけで描く。座標表は `src/presenter/views/dungeon-geometry.ts` に定数として持つ。
- UI-21 遠近は奥行きごとに固定の矩形（例: 奥行き 0 が画面いっぱい、3 が中央の小さな矩形）。側壁は隣接する奥行きの矩形を結ぶ台形。
- UI-22 線は `stroke-width: 1`、`shape-rendering: crispEdges`。塗りは無し。扉は正面壁の内側の小さな矩形。
- UI-23 歩行・旋回の演出は、ビュー全体を 60〜100ms フェードするだけ【仮】（線画のスライドはしない）。
- UI-24 マップ画面は別の SVG。探索済みセルを 8px 角で描き、壁は線、扉は隙間、階段は記号、現在位置は三角形（向き付き）。

## 4. 入力

- UI-30 スワイプはビュー領域で受ける（Pointer Events）。`pointerdown` の座標を起点に、移動量が `settings.swipeThreshold`（論理 28px【仮】、端末 px に換算）を越えた瞬間に、主軸（|dx| と |dy| の大きい方）で方向を確定して 1 回だけ発火し、`pointerup` まで再発火しない。上 = 前進、左右 = 旋回、下 = 反転。
- UI-31 前進を確定したまま指を離さなければ `settings.holdRepeatMs`（250ms【仮】）ごとに前進を繰り返す。壁に当たったら止める。戦闘・イベント・メニュー表示中は繰り返さない。
- UI-32 矢印ボタンも常に表示する。設定 `inputMode` で `swipe` / `buttons` / `both`（既定 both）。
- UI-33 PC ではキーボード: ↑ 前進、←→ 旋回、↓ 反転、Enter 決定、Esc 戻る、数字でメニュー選択。
- UI-34 iOS Safari のタブ表示では画面左端からのスワイプがブラウザの「戻る」になる。ビュー領域の左右に 12 論理 px の非反応帯を置く【仮】。
- UI-35 入力はすべて `Command` に変換して `execute` に渡す。表示層で入力の意味を解釈しない（例: 前進できるかの判定は core が `blocked` で返す）。

## 5. ダイスと演出

- UI-40 `dice` イベントは専用のダイス表示で見せる: ラベル、ダイスが 1 つずつ止まる演出（1 個 300ms【仮】）、合計。全滅ペナルティ、呪文習得、制止判定、逃走判定、先手判定で使う。
- UI-41 演出は `GameEvent` の `kind` ごとに `playback.ts` の 1 関数に対応させる。各関数は Promise を返し、`settings.skipAnimations` が真なら即座に解決する。
- UI-42 被弾: パーティ行のフラッシュ（`opacity` 2 往復、120ms）。敵の被弾: 敵の絵のフラッシュ。全体攻撃: ビュー全体の揺れ（`translate` ±2px、150ms）。すべて WAAPI。
- UI-43 メッセージの文字送りは `settings.textSpeed`（1 文字 30ms【仮】、0 で即時）。タップで残りを即表示。
- UI-44 イベント再生中の入力は無視する（ただしメッセージ送りのタップは受ける）。再生が終わってから次の入力を受け付ける。

## 6. 画面

- UI-50 タイトル: ゲーム一覧（SV-12）、設定。
- UI-51 簡易作成（プロトタイプ）: 6 行の名前入力（既定名あり）と性格の選択（リーダー行は「リーダー（性格なし）」固定）。「ランダム」ボタン。
- UI-52 街: 施設メニューとメッセージ。宿屋・寺院の各画面はリスト選択。
- UI-53 迷宮: §2 のレイアウト。メニューから道具・呪文（フィールド）・地図・並び順。
- UI-54 戦闘: ビューに敵グループ（絵、名前、体数）。操作領域にコマンド。全員分の入力が揃うと `battle.resolve`。オート切替ボタン。
- UI-55 イベント: メッセージと選択肢。衝動の行動者はパーティ行を点滅させて示す。
- UI-56 全滅: GM の語り → ダイス → ペナルティの内訳（失った金額、アイテム名、EXP と誰がレベルダウンしたか）→ 街へ。
- UI-57 設定: 演出スキップ、文字速度、入力モード、音量、書き出し・読み込み。

## 7. 素材

- UI-60 モンスター絵は 48×48〜64×64 の PNG【仮】、固定パレット、1 体 4〜6 色。`public/sprites/<monsterId>.png`。未鑑定は `<monsterId>_silhouette.png`（機械生成）。プロトタイプでは無ければ色付き矩形で代用する。
- UI-61 街の絵は施設ごとに 1 枚、240×150。プロトタイプでは無地でよい。
