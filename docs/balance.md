# バランス帳

数値の調整と計測の帳簿。2026-10-08（M12）から、数値の変更と計測の数字はこのファイルに書く。`docs/decisions.md` には判断の理由だけを書き、数字はここを参照する。

## 書き方

- 計測は `npm run balance`（Vitest。tests/balance/campaign.sim.ts、200 シード。M12 から BALANCE_SEEDS=<正の整数> でシード数を替えられる）。ログは scratchpad に `balance-<名前>.log` で残し、どのコミットで回したかを書く。
- M13 の農夫ボット（ハクスラの計測）は tests/balance/farm-*.sim.ts の 9 本（場所 × Lv。共通は tests/balance/farm.ts）で、`BALANCE_BOTS=farm npm run balance` で回す（BALANCE_BOTS=farm では campaign.sim.ts の 3 ボットは回らない。未設定なら全部回る）。
- 率は必ず「x.x%（件数/分母）」で書く。分母の小さい率は 1 件で大きく動くので、件数を見て判断する。
- 欠けているセル（その時点で集計が無い・ボットが無い）は「—」。
- 数値を変えたら「数値の変更の記録」に 1 行足す。1 つの変更を 1 行にし、前後の計測の名前（基準値の表の列か、decisions の計測の行の名前）と感触を書く。1 回の調整で変えるのは 1 項目だけにする（M14 はユーザーの指示で例外。複数項目を 1 回で変え、記録は項目ごとに 1 行。「目安と調整の順（M14）」）。
- data の個別の数値（敵・アイテム・ドロップ・ダンジョンの表）の【仮】の値はこのファイルの「コンテンツの数値」に書く。config.json の【仮】は今までどおり仕様書に付ける（CLAUDE.md §3-6）。
- 基準値の表の列は追記だけで、過去の列は直さない。

#### 農夫ボットの規則と回し方

- 編成: 既定の編成（config.prototypeParty）を街で `debug.levels`（UI-57）にかけて Lv3 / 5 / 8 にする。上がるのは HP・MP・呪文だけで、能力値は Lv1 のまま（state.rng も消費する）。所持金は初期の 300。店の装備は買わない（outfit 無し）。
- d02 に潜る分は、d01 を踏破した state にしてから始める（clearedDungeons に d01、unlockedDungeons に d02、shopLevel 2。初回クリアと同じ 3 点）。
- 潜行: 目標の階まで下り階段へ歩き、目標の階では上り階段から BFS 6 以内を歩き回る。帰る理由は各歩の後に full（全員の所持枠が満杯）→ time（推定の実時間の迷宮の分が 20 分）→ death（潜行の開始時に alive だった者の死亡）→ hp（前衛の alive の者の HP の合計が最大の半分未満）の順に見る。ほかの終わり方は wipe（全滅）と cap（歩数の上限）。帰りは糸（無ければ歩く）。8 戦の上限は使わない。
- 街: 救済 → 鑑定（未鑑定の装備品を見た目の売値の高い順に、払える限り店で）→ 装備の更新（鑑定済み・呪いなし・ユニークでない汎用装備だけ）→ 売却（装備していない装備品を、ユニークも含めて鑑定せずに今の状態で）→ 寺院 → 相部屋 → 補充（糸 1・薬草 6・解毒草 2）。純益は「売却の直後の所持金 − 潜行の前の所持金」で、宿・補充・寺院は純益の外に別に出す。
- 推定の実時間 = 拍の数 × 上の表の config.measure（実機の値）。迷宮の分は歩行・転換・遭遇・オートの 1 行動（beat declare）・勝利の締め・調べる / 解除・開ける・糸、街の分は鑑定・売却・宿。人の反応時間・ページの移動・前置きの語り・補充の購入・寺院・徒歩の帰りの階段の選択・逃走・罠の作動の演出・衝動イベントの語り・レベルアップの語りは含めない。

- 推定の実時間の注意: 拍の長さは実機(M13-拍) で Lv5 の d01 1 階で測った値で、人の反応時間を含まない。chestOpenMs（434）は品ありの箱では 773 に近い可能性がある（上の表の注）が、1 潜行の箱は数個なので影響は小さいと見ている（推測。数えていない）。
- d01 1 階の敵の Lv が Lv3・5・8 の 3 本とも 1 / 1 なのは、出現表が Lv1 の 2 種と重みの小さい Lv2 の giant_spider だけで、体数の平均が 1 に近いため（小数 2 桁は出していない）。
- 量の調整（ユーザーが決める。ここでは決めない）の提案: 候補 1（箱の中身の個数。drops.json の itemChance / rolls）か候補 2（敵ごとの直接ドロップ）で拾う品を増やす。ただし d01 2 階の律速は Lv4 以上の触媒なので、量だけでなく d01 2 階・d02 1 階の品の Lv（dropLevelSpread や基準 Lv）も合わせて見る。d02 1 階は Lv3 以上の 6 個と Lv4 以上の 3 個が同じ潜行数なので、量を増やすとどちらの項も下がる見込み（推測）。店で触媒が買える件の扱い（店の汎用装備を触媒にできなくする、流通レベルを下げる、そのままにする）も同じときに決める。
